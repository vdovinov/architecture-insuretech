# Анализ архитектуры InsureTech: проблемы и риски

## 1. Проблемы синхронного взаимодействия с ins-product-aggregator

| Проблема                                          | Риск сейчас и при росте до 10 страховых компаний                      |
|---------------------------------------------------|-----------------------------------------------------------------------|
| Синхронный опрос всех компаний при каждом запросе | Время ответа вырастет из-за самого медленной системы страховой компании |
| Отсутствие таймаутов и механизмов повтора         | При недоступности одной компании весь запрос падает                   |
| Периодические холостые опросы                     | Часть запросов возвращают неизменённые данные, но тратят ресурсы      |


## 2. Проблемы взаимодействия core-app и ins-comp-settlement

| Проблема                                     | Риск                                                         |
|----------------------------------------------|--------------------------------------------------------------|
| Ночной синхронный запрос всех данных за день | Пиковая нагрузка на БД core-app, риск таймаутов              |
| Отсутствие идемпотентности                   | При повторном запросе данные могут задвоиться                |
| Нет механизма досылки при сбое               | Если передача прервалась, данные за день могут быть потеряны |

## 3. Масштабируемость

| Проблема                                        | Риск                                                    |
|-------------------------------------------------|---------------------------------------------------------|
| Линейный рост времени ответа от числа партнёров | При 10 партнёрах время ответа станет неприемлемым       |
| Отсутствие асинхронности                        | Все потребители заблокированы на время опроса партнёров |

## Предлагаемые решения

1. Внедрение брокера сообщений (Kafka) для асинхронной публикации обновлений продуктов
2. Переход на событийную модель для оформления страховок
3. Использование паттерна Transactional Outbox для гарантированной доставки событий оформления страховок
4. Обновления реплик через подписку на события
